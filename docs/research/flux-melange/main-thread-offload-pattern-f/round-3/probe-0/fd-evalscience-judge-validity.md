## Findings

### inherit-tokens-conflated-with-subagent-lane
- Severity: P1
- Where: docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:23-24 (§What makes it enforceable rather than aspirational) crossed with interstat/scripts/profile.py:38-39,80-81,104-105,112,119,136
- What: CONFIRMED. profile.py's lane assignment (`lane = "subagent" if (sub_file or entry.get("isSidechain")) else "main"`, line 80) is computed purely from transcript file path (`is_subagent_file`, lines 38-39: `/subagents/` substring or `agent-` filename prefix) and the `isSidechain` flag. It never consults `model` for that decision — `model` is read on line 81 but only used as an aggregation-dict key, not as an input to lane assignment. The doc's own escape hatch (line 24, "Inheritance closed") explicitly permits "deliberate frontier-in-the-loop spawns" naming `model: inherit`, per item, with no stated per-goal cap. Because lane assignment is model-blind, such an inherit spawn lands in `agg[("subagent", "claude-fable-5-1")]` — the same lane bucket as a genuine `agg[("subagent", "claude-sonnet-5")]` executor. The summary stat the gate reads (lines 104-105/112/119: `lane_out[lane] += c["output_tokens"]`, then `main_output_share = lane_out["main"] / total_out`) sums across all models within a lane before the model dimension is dropped. So a goal where every "executor" spawn is actually a frontier model invoked via inherit still reports the same `main_output_share` as a goal executed entirely by real Sonnet subagents, as long as the main thread's own turns stay under 50%. The one number the doc calls non-aspirational ("a number on that report, not a feeling," line 23) cannot see this — the offload the design exists to enforce never happened, and the gate passes anyway.
- Evidence: profile.py:80 `lane = "subagent" if (sub_file or entry.get("isSidechain")) else "main"`; profile.py:81 `model = message.get("model") or "unknown"` (read, but not used for lane); profile.py:104-105/112 `lane_out[lane] += c["output_tokens"]`; profile.py:119 `"main_output_share": round(lane_out["main"] / total_out, 3)`; profile.py:136 prints only this single collapsed percentage. Doc:24 "Deliberate frontier-in-the-loop spawns name `model: inherit` explicitly" — no cap named anywhere in the doc.
- Suggestion: see cheap-fix-exists-but-unused below.
- Remediation: Add to "Inheritance closed" (or as a new open question) that the gate must attribute model:inherit subagent output tokens to a frontier-tier bucket distinct from genuine cheap-executor subagent tokens before the ≤50% number is trusted, since the escape hatch is uncapped per-goal and the current summary stat cannot see it.

### cheap-fix-exists-but-unused
- Severity: P1
- Where: interstat/scripts/profile.py:104-105,112,119 crossed with interstat/scripts/cost.py:106-126 (get_pricing)
- What: The smallest viable fix is already sitting in the same codebase. cost.py's `get_pricing()` (lines 118-125) already classifies any model string into a tier by substring match (`"fable" in model` / `"opus" in model` → frontier rates; `"sonnet"` / `"haiku"` → cheap rates) as a fallback when the model isn't in the explicit PRICING table. profile.py already imports `get_pricing` (line 23) but only uses it for `calc_cost` (line 107), never to gate which bucket a group's tokens count toward for the share the doc points the gate at. A small addition — classify each `(lane, model)` group into a second counter (e.g. `frontier_out += c["output_tokens"]` whenever `"fable" in model or "opus" in model`, independent of `lane`) — would let the summary report a `frontier_output_share` (main tokens + any-lane frontier-model tokens, over total) alongside `main_output_share`. That is the number the design's stated intent ("fewer, smaller main-thread turns" generated by non-frontier execution) actually needs; `main_output_share` alone is not it.
- Evidence: cost.py:118-125 (`if "fable" in model: return PRICING["claude-fable-5"]` / `if "opus" in model: return PRICING["claude-opus-5"]` etc.); profile.py:23 `from cost import calc_cost, get_pricing`; profile.py:107 is the only call site for `get_pricing`, feeding `calc_cost` only — no tier branch feeds `lane_out`.
- Suggestion: Add a `frontier_out` counter in profile.py's `main()` keyed off the same substring classifier cost.py already uses (or import a shared `is_frontier_model()` helper from cost.py), and report `frontier_output_share` as a second, gate-eligible stat next to `main_output_share` in both the text and `--json` output.
- (no remediation beyond the one already given under the parent finding — this is a code fix, not a further target-doc amendment)

### codex-lane-invisible-to-meter
- Severity: P2
- Where: docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:23,32 (§A meter that sees lanes; Q-C) crossed with interstat/scripts/profile.py:25,46
- What: Q-C names a third execution lane ("The codex lane is cost-free relative to the Claude pool but sandboxed and slower... Sylveste-d3m phase 1 builds the shadow corpus") that pilots are expected to route some items through. profile.py's `PROJECTS_ROOT` (line 25) is hardcoded to `~/.claude/projects`, and its glob (line 46) only walks that tree for `*.jsonl`. If Codex CLI sessions log to a separate store rather than that directory, codex-routed output tokens for a goal never enter `agg` at all — not misclassified into "main" or "subagent," simply absent from both `lane_out` and `total_out`. That moves `main_output_share` in the opposite direction from the inherit-laundering finding above: undercounting a real non-main-thread channel shrinks the denominator without shrinking the main-thread numerator, which can only push the reported main-thread share up. So this gap risks a false FAIL — a goal that legitimately offloaded a large share of work to codex could still show >50% main-thread share on the meter — rather than the false PASS the inherit gap produces, and is worth resolving before Sylveste-d3m's shadow-corpus pilots are scored against this same gate.
- Evidence: profile.py:25 `PROJECTS_ROOT = os.path.expanduser("~/.claude/projects")`; profile.py:46 `glob.glob(os.path.join(PROJECTS_ROOT, "**", "*.jsonl"), recursive=True)`; doc:32 "Q-C: The codex lane is cost-free relative to the Claude pool but sandboxed and slower... (Sylveste-d3m phase 1 builds the shadow corpus)".
- Suggestion: Before scoring any pilot that routes items to the codex lane against the ≤50% gate, confirm whether codex session transcripts are reachable from profile.py's glob (or by an equivalent codex-side collector) — if not, either merge a second collector into the same `total_out` denominator, or have the gate explicitly disclaim that it covers Claude-pool lanes only.
- Remediation: Add a note to Q-C (or a new open question) asking whether interstat/scripts/profile.py's glob root reaches codex-lane transcripts, since as written it scans only `~/.claude/projects` and a codex pilot could otherwise be scored on an incomplete denominator.

## Verdict
CONFIRMED as the dominant, well-grounded finding: profile.py's lane classification is model-blind by construction (path/isSidechain only), so the doc's own uncapped `model: inherit` escape hatch can populate the "subagent" bucket with frontier-generated tokens the single ≤50% summary number cannot distinguish from genuine cheap execution — and the fix is cheap, since cost.py already carries the model-tier classifier profile.py needs but never applies to the gate stat. A second, opposite-direction gap (codex-lane tokens excluded from the denominator entirely) is worth resolving before Sylveste-d3m pilots are scored, though it biases the gate toward false failures rather than false passes.
