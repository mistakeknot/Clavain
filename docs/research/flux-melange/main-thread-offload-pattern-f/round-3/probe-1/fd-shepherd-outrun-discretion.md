## Findings

### codex-lane-escalation-mismatch
- **Severity**: P1
- **Where**: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:16` (executor role, "or the codex lane for classes with parity"), crossed with `:19` (escalation: two remedies) and `:32` (Q-C: "sandboxed and slower... which pilot classes should go there first").
- **What**: The escalation contract names exactly two remedies for a strike: the orchestrator "fixes the plan... or takes the item frontier-in-the-loop." Both remedies assume the strike means something about the *plan*. But line 16 admits a second kind of dog — the codex lane — and calls it "sandboxed," a word that describes what the worker can *reach*, not what it knows or how carefully it works. A verify block that depends on something the sandbox denies (network egress, a live service, a resource the Sonnet lane has and codex doesn't) will fail on the codex lane and pass on the Sonnet lane, for reasons that have nothing to do with the plan being wrong. Two such strikes trigger the same two remedies as a genuinely defective plan: the orchestrator rewrites criteria that were never wrong, or escalates to frontier for an item that only needed the other lane. Q-C frames the open question as *sequencing* ("which pilot classes should go there first") — that phrasing presupposes "parity" is already a settled yes/no property of a class, checked somewhere before Q-C's ordering question even applies. Nothing in the document says where that check happens or what it tests. A shepherd sending a second dog onto ground the first dog could cross doesn't ask "which field first" until they know the second dog can smell the same ground.
- **Evidence**: Line 16's parenthetical ("or the codex lane for classes with parity") is the only place "parity" is asserted; it is never defined. Line 19's escalation clause is exhaustive ("fixes the plan... or takes the item frontier-in-the-loop") with no third branch. Line 32 (Q-C) asks only about pilot-class ordering, not about a parity test.
- **Suggestion**: Give the escalation contract a third message: a strike report that names *lane mismatch* as distinct from *plan defect* (e.g., the executor's report can state "verify block could not run in sandbox: <resource>" instead of a criterion failure). That single new report shape lets two-strikes distinguish "the plan is wrong" from "this class doesn't have parity yet," and answers Q-C's real prerequisite before it answers Q-C's stated question.

### inheritance-default-not-contract-adoption
- **Severity**: P1
- **Where**: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:24` ("Inheritance closed... makes every unpinned spawn (48 command/skill sites, 25 doc-shaped agents) resolve to Sonnet"), crossed with `:16` (the executor's actual contract: one plan path in, verbatim verify output out, never expand scope) and `:21` (the bullet is filed under "What makes it enforceable rather than aspirational").
- **What**: `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` changes which model answers when one of 73 existing call sites spawns a subagent. It does not touch what those 73 sites ask for or what shape of answer they accept — most of them predate Pattern F and were never written to hand out one plan-file path, demand a verify block, or accept only "verbatim verify output" back. Swapping the model at those sites is a lane change, not a contract change: a maid-of-all-work dog answering the whistle doesn't become a purpose-trained one because you changed which dog you called. The document lists this bullet as evidence Pattern F is enforceable, but it only demonstrates that the *default model* is enforced project-wide — not that Pattern F's actual discipline (frozen criteria, no scope expansion, one report shape) is present at any of those 73 sites. Someone reading "48 spawn sites... resolve to Sonnet" as evidence of Pattern F's rollout would be reading a claim the document doesn't make but is positioned to imply.
- **Evidence**: Line 24 is the entirety of the inheritance mechanism described; it names a model default and an escape hatch (`model: inherit`), never a prompt contract. Line 16 is the only place the executor's actual speaking-rules are stated, and nothing ties it to the 48+25 sites.
- **Suggestion**: Split the bullet's claim in two, or narrow it: "Inheritance closed" is evidence that *spend* moves off the main model at unpinned sites; it is not evidence that *Pattern F's message contract* exists there. If the intent is for those 73 sites to eventually speak Pattern F's dialect too, say so as a separate, unstarted line item — don't let the model-default bullet stand in for it under "enforceable."

### no-reader-for-the-unasked
- **Severity**: P2
- **Where**: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:7` (the 30-day transcript analysis that produced this document's own headline number), crossed with `:16-17` (executor and validator report contracts) and `interstat/scripts/profile.py:38-39,80,104-123` (lane/session split and the fixed metric set it emits).
- **What**: This document exists because someone read across 87K assistant messages and noticed something nobody had asked about in advance — that 85% of main-thread cost was context, not generation. `profile.py` confirms the raw substrate for that kind of noticing survives Pattern F: it walks `~/.claude/projects/**/*.jsonl` and classifies subagent files itself (`is_subagent_file`, `isSidechain`), so executor and validator transcripts are not discarded. But what the tool *emits* is a fixed set of asked-for numbers — `main_output_share`, `main_cost_share`, `ctx_per_msg` — the same shape of question this very design closes off elsewhere (§The look: nothing exists purely to notice). Once execution is dispersed across many disposable, narrow-report subagent runs and the orchestrator's own turns shrink toward the ≤50% target, is anyone still positioned to read transcripts end-to-end the way the original 30-day analysis did, or does the next unrequested pattern — the one profile.py wasn't built to ask about — now have no reader at all, only a meter?
- **Evidence**: `interstat/scripts/profile.py:38-39` (subagent detection by path/marker, confirming transcripts persist), `:104-123` (the aggregation loop and the three summary fields it computes — nothing broader). Doc `:7` for what the original open-ended read found; `:16-17` for how thin the new steady-state reports are by contract.
- **Suggestion**: Not a design change to Pattern F itself — a question for the pilot review: name who (or what cadence) does an open-ended read of a sample of subagent transcripts after the pilots, the way the 30-day read that produced this document did, rather than relying on `profile.py`'s fixed fields to surface whatever the *next* unasked-about pattern turns out to be.

## Verdict
The strongest new material here is the codex lane: Q-C's own phrasing ("which pilot classes go there first") quietly assumes a parity check that the document never locates, and the two-strikes contract has no message for the specific way a sandboxed dog fails that a Sonnet dog wouldn't. The inheritance-default finding is the same species of gap at the plan-quality level — a bullet doing double duty as evidence of the wrong thing. The transcript-reader finding is real but softer, correctly demoted to P2 and flagged as a question rather than an assertion since the raw data confirmably survives; the loss, if any, is in who reads it, not in what's kept.
