## Findings
### failed-work-improves-the-offload-gate
- Severity: P0
- Where: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:15-19,23`; `scripts/orchestrate.py:792-847`; `/Users/sma/projects/Sylveste/interverse/interstat/scripts/profile.py:103-123`
- What: The sole enforceability gate is directionally inverted for the two-strike path. `profile.py` puts every observed delegated output token into the denominator without conditioning on approval or a landed outcome, while the pipeline creates another fix and review episode after each rejection and finally hands an escalated item back to the frontier main thread. Thus a clean first-pass item can score worse than an item that spends two downstream strikes, leaves committed or otherwise path-dependent state for the controller, and then consumes a large main-thread recovery turn. A concrete Goodhart adaptation is to retain verbose fix/review rounds or split one item into more validator-visible episodes: the share moves toward 50% even though the protected surface, rework, and recovery burden grow. This can cause all pilots to certify the architecture on the very failure path the gate was supposed to discourage.
- Evidence: The design defines success as the orchestrator generating no more than 50% of goal output tokens and routes two rejected rounds back to the orchestrator (`Pattern F:15,19,23`). The loop dispatches a fresh fix after each failed verify/review and escalates only after the round budget (`orchestrate.py:792-847`). The meter sums output solely by lane and model, then computes `main / (main + subagent)` with no task status or quality term (`profile.py:103-123`). The canonical doctrine also records that the literal gate missed at 86% while main cost share fell to 35%, and says the generated-token gate was wrong (`commands/model-routing.md:165-175`).
- remediation: Replace the <=50% generated-token gate in the brief with a ratified outcome-qualified reserve-accounting scorecard that reports absolute main and delegated cost/context, failed-attempt resources, landed quality, inspection stage, and residual mutations.
- intersection_justification: The observability parent contributes the unconditional ratio and its failure-denominator incentive; the batik parent contributes the fact that each added strike starts later in an ordered process with less clean protected ground and a narrower repair window; only their intersection shows that the gate positively rewards costly reserve loss rather than merely omitting cost or merely retrying from altered state.

### reserve-accounting-cells-cannot-be-joined
- Severity: P1
- Where: `/Users/sma/projects/Sylveste/interverse/interstat/scripts/profile.py:42-88,103-123`; `scripts/orchestrate.py:965-1045,1174-1189`
- What: No emitted record can instantiate the charter's fused primitive—a workload coordinate crossed with the resist-process coordinate active at that event. Interstat can currently capture timestamp-window/session filtering, lane, model, message count, input/output tokens, cache-read/cache-write volume, context per message, and API-equivalent cost. Orchestrator metadata can separately capture task, phase, return status, and duration. Neither side records a common goal/run/task/attempt/phase/session identifier, and the task journal records only the final HEAD and aggregate round count, not the pre/post state or reserve identifier for implement, verify, review, and each fix. Retrospective joining is therefore ambiguous once later commits or fixes mask the state each reviewer actually encountered.
- Evidence: `collect()` aggregates directly into `(lane, model)` after optional time/session filtering (`profile.py:42-88`) and the output rows contain no goal, task, attempt, or phase (`profile.py:103-123`). Per-dispatch `meta.json` has task/tier/phase/duration/status but no engine/model session, usage, pre/post HEAD, porcelain fingerprint, or reserve reference (`orchestrate.py:1037-1045`). The terminal journal collapses the pipeline to `rounds`, the last result duration, one review verdict path, and the current final HEAD (`orchestrate.py:1174-1189`). For an ordinary item this erases the cost and state coordinates between implement and review; for a two-strike item it also prevents attributing rework and frontier recovery to the boundary leak that caused them.
- Suggestion: Emit one append-only stage event for every implement, verify, review, fix, escalation, and landing transition with goal/run/task/attempt/phase, engine/model/session, token/cache/queue/wall counters, pre/post HEAD and porcelain fingerprints, reserve-manifest ID, parent attempt, and outcome, then teach the profiler to join on that event ID.
- intersection_justification: The observability parent contributes the available usage fields and the missing attribution join; the batik parent contributes the stage-local reserve, pre/post state, and masking transition that make otherwise identical token events non-equivalent; neither alone establishes why aggregate telemetry cannot measure information gained while correction was still local.

### parallel-decomposition-duplicates-work-and-exposure
- Severity: P1
- Where: `skills/writing-plans/SKILL.md:178-214`; `scripts/orchestrate.py:531-564,753-800,1081-1100`; `/Users/sma/projects/Sylveste/interverse/interstat/scripts/profile.py:80-87,115-123`
- What: The recommended decomposition can improve the apparent offload shape by creating more executor/reviewer work while simultaneously destroying task-local review boundaries. `writing-plans` automatically emits a parallel manifest for three independent tasks; the orchestrator runs those tasks concurrently in one `project_dir`, snapshots each task's HEAD at dispatch, and later labels the whole repository diff from that HEAD as task-scoped ground truth. If task A commits before task B's review, B's validator consumes A+B, emits additional delegated tokens over duplicated evidence, and may reject A's out-of-scope changes; B's fix agent is then ordered to address every finding on protected ground it does not own. The meter aggregates that duplicated traffic without a task/diff-ownership coordinate, so the pilot cannot tell useful offload from extra work induced by cross-task exposure.
- Evidence: Plans with at least three independent tasks are automatically manifested and may use `all-parallel` (`writing-plans:178-214`). `dispatch_batch()` submits every ready task against the same `project_dir` to a thread pool (`orchestrate.py:1081-1100`); each pipeline captures `head0` independently (`orchestrate.py:753-772`); `task_diff()` then takes every committed and uncommitted repository change since that HEAD, capped only by line count (`orchestrate.py:531-564`), and passes it to the reviewer as ground truth (`orchestrate.py:794-800`). Interstat collapses observed work to lane/model totals (`profile.py:80-87,115-123`).
- Suggestion: Before pilot scoring, either isolate parallel tasks or bind each review event to an ownership-filtered diff plus pre/post repository fingerprint, and count duplicated or foreign-diff review tokens as contamination rework rather than productive delegation.
- intersection_justification: The observability parent contributes the decomposition/duplication accounting error and missing ownership attribution; the batik parent contributes the shared-worktree reserve breach in which another task's layer enters the validator's inspection surface before the local boundary is judged; only together show that the token gate rewards a topology whose extra measured work is caused by loss of protected task ground.

### q-a-asks-the-wrong-experiment
- Severity: P1
- Where: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:16-19,30`; `commands/model-routing.md:157-175`; `scripts/orchestrate.py:772-800,829-836`
- What: Q-A's binary premise—validator information versus validator cost—is no longer the decision. The canonical doctrine records five code-correct executor runs and six real validator findings outside the gauges, so the role has demonstrated information gain; the still-open question is whether Opus adds marginal information beyond a cheaper validator and whether it sees the defect before or after the locally repairable boundary. The current pipeline reviews only after execution, machine verification, and the executor's commit, then reviews a cumulative diff after a fix. Treating any later finding as “Opus value” prices model output but ignores whether the same fact was cheaply observable pre-commit or whether the review merely classified damage after its causal evidence was masked.
- Evidence: The brief says the pilots will determine whether Opus catches anything missed by the verify block (`Pattern F:30`). The canonical doctrine says the pilots already ran, validators found six real gauge omissions, and “Q-A resolved” while the literal token gate proved wrong (`model-routing.md:157-175`). The implementation fixes inspection placement after `head0` → executor → verify → review, and after rejection sends a fix before the next cumulative review (`orchestrate.py:772-800,829-836`). This evidence establishes validator-role value but, as the settled facts state, does not establish Opus's unique contribution.
- remediation: Replace Q-A with “At which pre-commit or post-commit boundary does validation add marginal, still-actionable information, and does Opus add more of it per resource unit than a cheaper validator?”
- intersection_justification: The observability parent contributes marginal information per model/resource unit and the need for a comparator; the batik parent contributes inspection placement, remaining repairability, and the distinction between observing a penetrable boundary and judging the finished layer; only the combination invalidates Q-A's role-level binary without overclaiming that the existing evidence identifies the best validator model.

## Verdict
Pattern F's current gate can improve as failures, duplicate reviews, and late repair accumulate, while the available telemetry cannot join those resources to the reserve boundary that produced them. Q-A has the wrong premise: validator-role value is already observed; the pilot-worthy question is Opus's marginal information at a still-repairable stage.
