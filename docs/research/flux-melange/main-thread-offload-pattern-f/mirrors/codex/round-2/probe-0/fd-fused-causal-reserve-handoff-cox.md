## Findings

### contract-is-not-an-atomic-causal-reserve-cell

- Severity: P0
- Where: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:15-17` (§The shape); `scripts/orchestrate.py:353-356,446-466,582-612,786-800,1412-1419,1443-1450`
- What: Pattern F says the executor and validator receive the same plan and frozen criteria, but the current handoff has no atomic causal-reserve cell. At run start the orchestrator parses a plan section and verify entries into memory; later the executor is told to read the live plan path, while the reviewer receives the earlier parsed section and is separately told to read the live criteria path. The run journal records paths, not content identities. A clean-looking attempt can therefore execute plan revision B, run revision-A gates, and judge a revision-C reserve boundary. Concrete failure: after dispatch, a coordinator adds “preserve the public JSON field” to the criteria or plan; the fresh executor changes that field under the other revision, the old verify block passes, and the validator's PASS is not attributable to any single contract or protected ground. The landed result can violate the intended API even though every stage reports success.
- Evidence: `parse_plan_tasks()` reads the plan once and stores its section and verify entries (`scripts/orchestrate.py:446-466,1412-1414`); `build_prompt()` gives the executor only the live plan path and instructs it to read that file (`:353-356`); `build_review_prompt()` embeds the captured section but hands the reviewer a path to whatever criteria file exists then (`:603-612`); `run_task_pipeline()` combines those captured entries with a later live repository diff (`:786-800`); and the journal's run-start record persists only plan/manifest paths (`:1443-1450`). No plan revision, criteria digest, base snapshot, attempt identity, or stage-bound reserve digest is checked across those transitions.
- Suggestion: Materialize one immutable per-task envelope in the run directory containing the plan-section and criteria digests, base commit/tree, attempt ID, declared edits, compact protected-reserve manifest, and required inspection stage; make executor, gate, reviewer, and landing verify and echo that envelope ID before acting.
- intersection_justification: The distributed-systems parent contributes the mixed-time state-transfer failure: path identity is mistaken for immutable plan/criteria identity across independently scheduled stages. The batik parent contributes the fact that a criteria revision changes the masking layer—what must remain untouched and when it can still be inspected—not merely positive instructions. Jointly, a PASS is bound to no causal-reserve cell; remove causal versioning and the reserve cannot be associated with the state reviewed, while removing the reserve dimension leaves only an ordinary stale-artifact bug.

### parallel-review-cannot-attribute-reserve-leakage

- Severity: P0
- Where: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:15-17` (§The shape); `skills/writing-plans/SKILL.md:144-176,178-214`; `scripts/orchestrate.py:46-54,154-174,531-564,582-629,771-800,1057-1120,1497-1525`
- What: “Task-scoped” review is not task-scoped when ready tasks run concurrently in the same repository. Every task snapshots only the current `HEAD`, then its validator receives every committed and uncommitted change since that `HEAD`; the manifest carries positive `files` and dependencies but no per-task protected surface or ownership of generated effects. Concrete failure: tasks A and B start at H; A edits its declared file, while B's verification regenerates an undeclared shared snapshot that should have remained fixed for A. A's reviewer sees A, B, and the snapshot in one cumulative diff. It can reject A and spend a strike for B's authorized work, or ignore the extra change and PASS without knowing which attempt leaked across the snapshot reserve. A later dependent consumes the contaminated snapshot after the local attribution window has closed, so the orchestrator can land a state no individual review actually attested.
- Evidence: the manifest schema records only positive `files`/`depends` (`scripts/orchestrate.py:46-54`; `skills/writing-plans/SKILL.md:155-176`), graph validation checks references and cycles rather than reserve overlap (`scripts/orchestrate.py:154-174`), and the plan author is told to infer parallelism from declared dependencies/file independence (`skills/writing-plans/SKILL.md:178-214`). `dispatch_batch()` runs ready tasks in a shared `project_dir` thread pool (`scripts/orchestrate.py:1057-1120`); each pipeline captures `HEAD` just before dispatch (`:771-777`); `task_diff()` then collects the whole repository delta from that commit, including all untracked files (`:531-564`); and the prompt labels this cumulative material “the diff since this task started (ground truth)” (`:582-629`).
- Suggestion: For the pilots, fail closed to sequential execution unless each task has an isolated worktree or an attributable commit delta plus a reserve manifest; reject a review whenever its observed delta contains a path/effect belonging to neither the task's edit set nor its explicitly permitted incoming state.
- intersection_justification: The distributed-systems parent contributes concurrent writers, per-task snapshot identity, and the loss of authorship when cumulative repository state is passed as one task's evidence. The batik parent contributes the undeclared generated/shared artifact as protected ground and the intermediate window in which its boundary leak is still attributable. Together they show why neither a commit SHA alone nor a static protected-file list can validate this shared-worktree run; remove concurrency and the leak remains locally attributable, while remove the reserve boundary and the issue reduces to ordinary diff contamination.

### q-a-uses-validator-role-as-experimental-unit

- Severity: P1
- Where: `docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:17,28-30` (§Open questions the review should attack); `scripts/orchestrate.py:582-629,667-745,786-818`
- What: Q-A asks whether “the validator” adds information or only cost, as though marginal information were a property of Opus versus executor verification. In this architecture the same validator can be informative at one causal-reserve cell and redundant or misleading at another: it can independently inspect a protected boundary before the next mutation, merely replay a final gate after the reveal window is gone, or observe a different repository/criteria state and appear to catch a defect that is actually drift. Counting Opus catches cannot distinguish those cases, so even a pilot result cannot answer Q-A as written.
- Evidence: the target gives the validator the final plan/report and asks it to rerun the final verify block (`docs/brainstorms/2026-09-03-main-thread-offload-pattern-f.md:17,30`), while the current pipeline builds the review from a previously produced verify report plus a live diff (`scripts/orchestrate.py:582-629,786-801`) and accepts the later sidecar verdict (`:667-745`). Neither description defines the observation as `(plan revision, base snapshot, result state, attempt) × (protected invariant, stage, checkpoint)`, so a catch or miss has no stable denominator for “information added.”
- Suggestion: In each pilot, classify validator observations by causal-reserve cell and count only defects found on the same state/contract that executor verification attested, recording whether the boundary was still locally repairable.
- Remediation: Replace Q-A with the question “At which causal-reserve cells does an independent validator observe protected-boundary evidence unavailable to executor verification, and at what marginal cost?”
- intersection_justification: The distributed-systems parent contributes the requirement that executor and validator observations be bound to the same plan, attempt, and repository state before their signals can be compared. The batik parent contributes placement at the reserve boundary's reveal-and-repair window, without which a later observation may contain no recoverable information. Only their intersection identifies the experimental unit; remove causal identity and catches conflate drift, while remove the stage-specific reserve and Q-A collapses back to a generic model-comparison question.

## Verdict

Pattern F is not ready for pilots: its nominally frozen contract is assembled from different moments, and concurrent task review destroys attribution precisely where protected ground can leak. Q-A also has the wrong premise; validator value belongs to a causal-reserve cell, not to the validator role in the abstract. The partial-retry trace yielded no additional conjunctive finding beyond the settled retry evidence and was discarded.
