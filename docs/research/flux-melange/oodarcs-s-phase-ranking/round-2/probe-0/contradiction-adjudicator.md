## Findings

### slacken-is-config-reachable-not-a-call
- **Severity:** P1
- **Where:** `docs/research/2026-08-24-oodarcs-s-phase-ranking-charter.md:36` (disputed location), with `:46-48` and `:61`
- **What:** Adjudicating the pair: **(2) holds on the kind-claim and dominates; (1) is real but cannot express the defect; and (2)'s stated premise is factually wrong in a way that reverses its own prescription.** Not an irreducible taste call — three code facts decide it.

  **(2) is right that Slacken is not a call.** `acCfg` is constructed inside `runWithContent` (agent.go:227-229) from `DefaultAutoCompactConfig()`'s hardcoded constants — `BufferTokens: 13000`, `KeepRecent: 6`, `OutputReserve: 8192` (autocompact.go:56-64) — with only `PostCompactHook` assigned. Nothing the model emits, and no phase transition, can move it. Contrast the two dials that *are* run-scoped calls: `SetModelOverride` (agent.go:137) and `SetThinkingBudget` (agent.go:154) are on the `Agent` surface and wired to TUI commands (tui/app.go:583,:602; tui/commands.go:622). Slacken has no such seat and no analogue of one. So Slacken cannot answer `:46` (distinct semantic operation) or `:47` (distinct runtime phase) at all — those verdicts require something invocable, and a constant is not invocable. It is ineligible for the class requirement 4 ranks, not merely weak in it.

  **(2) is wrong that the seat is "unreachable."** The compaction trigger is `tokenCount >= (router.ContextWindow(model) - OutputReserve) - BufferTokens` (loop.go:147-149, autocompact.go:101-106). `ContextWindow` is config-overridable per model: `context_windows` in the routing config, merged base-then-project (router/config.go:17,:103-104; router.go:230-236), loaded at startup including a project-level file (main.go:131-138). A pilot can therefore move Slacken's clock **today, by config file, with zero code change** — it is a composition-time parameter that is reachable, not an unreachable one. This confirms rather than defeats round 1's relocation of Slacken into requirement 8 as the clock-only control arm, and removes its cost objection.

  **Why (1) is subordinate and its remedy is the trap.** No rating vocabulary can express "wrong kind of object"; a scale returns a position, and a position implies membership. Worse, `:61` "enforceability in an agent harness" is one of the *few* criteria that is not a declared tie (it reads on the harness, not on absent observations), so under the settled facts it will effectively carry the ranking — and it is inverted: a hardcoded constant no agent can address is maximally enforceable *because* it is not a call, while Stint and Divert, whose triggers read model-produced state (shear record, stagnation signal), are less enforceable precisely because they are invocable and therefore gameable. Supplying the vocabulary finding (1) asks for would rank Slacken first on the strongest live criterion for exactly the property that makes it ineligible.
- **Evidence:** `internal/agent/agent.go:227-229` (per-turn `acCfg` from constants; only `PostCompactHook` set), `:137`,`:154` (the run-scoped setters Slacken lacks); `internal/agentloop/autocompact.go:56-64` (constants), `:101-106` (threshold as pure function of tokenCount); `internal/agentloop/loop.go:147-149`; `internal/router/router.go:220-236` and `internal/router/config.go:17,:103-104` (`context_windows` override); `cmd/skaffen/main.go:131-138` (base + project routing config load); target `:36`, `:46-48`, `:61`. Ledger f-071 (synthesis `:187`) reads the same "built once per Run" fact as proof of a *real* enforcement seat — both readings of the fact are true, and they answer different questions: the lever binds (yes), an agent can fire it (no).
- **Suggestion:** Record Slacken's disposition as **ineligible for verdicts 1-2, scheduled for requirement 8**, and state its pilot recipe concretely: per-arm project routing config with `context_windows` lowered/raised for the routed model, everything else identical. Replace the `:61` scalar with a two-field eligibility record on every row — *seat* (in-band call / composition config / code constant) and *addressee* (model / operator / neither) — filled before any rating, so a kind error is caught by the form rather than absorbed into a score.
- **Remediation (target amendment):** Amend requirement 4 to rank only claimants with an in-band or operator-addressable seat, and replace criterion `:61` with a pre-rating eligibility record of each candidate's seat (in-band call / composition config / code constant) and addressee (model / operator / neither).

### compaction-discards-the-treatment-by-construction
- **Severity:** P0
- **Where:** `docs/research/2026-08-24-oodarcs-s-phase-ranking-charter.md:40`, against `:36`
- **What:** New insight the contradiction exposes. Chasing "which clock does Slacken actually seat in" shows there is not one compaction clock but **two**, with different discard laws, and requirement 8's "identical … compaction treatment" governs neither.

  1. **Loop clock** (both modes): fires at `effectiveWindow - 13000` before each LLM call (loop.go:147-149); discards **positionally** — `microCompact` stubs the oldest tool results, `snip` drops the oldest messages outside a 6-message tail (autocompact.go:56-64,:135,:194).
  2. **TUI clock** (TUI only): fires post-turn when `contextPct > 80`, where the denominator is a hardcoded `contextMaxTokens = 200_000` regardless of the model actually routed (tui/status.go:14-15; tui/app.go:872-890); discards **by relevance score** — `session.ScoreMessages` gives mutation results 10.0, write/edit calls 8.0, bash 5.0, reads/greps 4.0, assistant reasoning text 2.0, user text 1.0, +3.0 for touching an actively-edited file (session/scoring.go:38-47,:106-160), keeps only `k = len/2` plus 4 recent, and renders the survivors through a phase-detected `CompactIntent` (tui/commands.go:888-921; tui/compaction_state.go:81).

  Consequences for the pilots that all three verdicts at `:44-48` rest on:
  - **The selection law is anti-correlated with every S candidate's product.** Exploration output *is* reads, searches and reasoning about leads that went nowhere — the 2.0-to-4.0 band. Edits are 8.0-10.0. The TUI clock preferentially deletes the exploring arm's evidence and preserves the exploiting arm's, so a blind score of "disconfirmed hypotheses retained" measures the retention heuristic, not the arm.
  - **Identical settings do not produce identical treatment.** Both triggers are pure functions of tokens the arm itself consumed, so the arm that explores more compacts sooner and more often even with byte-identical config. Holding compaction "identical" holds the confound fixed; it does not remove it.
  - **The regime is mode-dependent and undeclared.** Headless (`--mode print`, main.go:99-105,:208) never constructs a TUI, so clock 2 and the relevance scoring never run: a headless pilot measures positional truncation, while the design, if shipped, lives under mutation-scored retention. `:40` names task buckets, stores, budgets and compaction — not execution mode.
  - **The two clocks disagree.** Clock 2's fixed 200k denominator is not clock 1's `router.ContextWindow(model)`; with a per-phase model of a different window (or a `context_windows` override), the order in which the two fire flips mid-session, so the discard law in force varies by phase.
- **Evidence:** `internal/tui/app.go:872-890`; `internal/tui/status.go:14-15`; `internal/tui/commands.go:888-921`; `internal/tui/compaction_state.go:81-107`; `internal/session/scoring.go:38-47`,`:106-160`; `internal/agentloop/loop.go:147-149`; `internal/agentloop/autocompact.go:56-64`,`:101-106`; `internal/agent/agent.go:227-229`; `cmd/skaffen/main.go:99-105`,`:208`. Ledger f-071 identifies only the timing half of this on clock 1; the selection half and clock 2 are unfiled.
- **Suggestion:** Fix and declare one execution mode for all arms; log per arm and per turn the snip count, `microCompact` bytes elided, TUI compaction count, and the retained/discarded counts bucketed by `scoreMessage` class, as predeclared covariates; and score retention of disconfirmed leads only from the durable evidence record, never from surviving context. If arms must run in the TUI, disable the settings toggle `auto-compact` (tui/settings.go:109-118) for all arms so only the positional clock is live.
- **Remediation (target amendment):** Amend requirement 8 to fix and declare a single execution mode for every arm and to require per-arm logging of both compaction paths (loop snip/microCompact counts and, in TUI mode, `ScoreMessages` retention bucketed by tool class), since "identical compaction treatment" controls neither the trigger nor the selection law.

## Verdict
The kind-claim wins: `acCfg` comes from constants with no `Agent`-surface setter, so Slacken is a composition parameter and is ineligible for the semantic-operation and runtime-phase verdicts — but it is *config-reachable* today via `context_windows`, so the correct disposition is scheduling it as requirement 8's clock-only control arm, not scoring it out. Finding (1) survives as a real but subordinate defect whose remedy is a trap here, because `:61` "enforceability" is inverted: it awards its maximum to whatever cannot be invoked. Chasing the seat exposed the larger problem — two compaction clocks, one of them mutation-scored and TUI-only, that delete the exploring arm's product by construction and are not controlled by anything requirement 8 mandates.
