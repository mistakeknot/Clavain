## Findings

### equal-budget-names-no-currency

- **Severity:** P0
- **Where:** `docs/research/2026-08-24-oodarcs-s-phase-ranking-charter.md:40` ("Produce minimal pilots for the top two actionable designs and the no-S null using identical task buckets, stores, budgets, and compaction treatment").
- **What:** "Identical budgets" names no currency. In this runtime the currency is a config field with a default, and the arms differ from the null precisely along the axis the default ignores — so "equal budget" silently subsidizes or taxes the treatment arm and every headline comparison is uninterpretable regardless of outcome.
- **Evidence:** Verified in the repo, not inferred from the prior run. `internal/router/config.go:25` — `Tracking string \`json:"tracking"\` // "billing" (default), "context"`. `internal/router/budget_test.go:150-166` confirms the default path: with no `Tracking` field set the tracker reports `billing`, and `budget_test.go:140-142` states "billing mode: only 100 + 100 = 200 (cache tokens ignored)". The S arms differ from the null by parking speculative material in cached context — Fallow withholds S-tasking, Survey adds untriggered sampling, Slacken changes the base clock — so under the default currency the exploration arm's parked material is free, and under `context` it is charged. The prior run filed this as f-044 and the synthesis **raised its likelihood 2→3 "because the default is in the code."** The charter's `:26` acknowledges "current pilot instrumentation is confounded" as a claim to verify, and its only repair step (`:31-34`) is scoped to the *field* (Stress-test, Simulate), not to the pilot — so no clause requires the currency to be named. **Failure scenario:** the Fallow/no-S pilot runs at "equal budget," the null arm exhausts its allowance on Orient's per-turn re-strike while the Fallow arm's withheld tasking leaves cached context uncharged, Fallow posts a better turns-to-useful-probe number, and the recommendation to adopt an allocation policy rests on a metering artifact. Nobody can tell from the artifact which way the subsidy ran.
- **Suggestion:** Amend `:40` to: "...using identical task buckets, **isolated stores**, and a **named budget currency** — set `Tracking` explicitly to `context` for all arms (`internal/router/config.go:25`) and record the setting in the pilot pre-registration — and identical compaction treatment."

### identical-stores-is-the-wrong-instruction

- **Severity:** P1
- **Where:** `:40` ("identical ... stores").
- **What:** As written, "identical stores" is satisfied by the arms sharing one store — and in this runtime that is not merely permitted, it is the only reachable configuration. The incumbent Orient read path then feeds each arm the other arm's rows.
- **Evidence:** The store is a single user-global path with no override. `cmd/skaffen/main.go:290` and `:526` — `mutations.NewStore(filepath.Join(cfg.UserDir(), "mutations"))`; `internal/config/config.go:34` — `userDir: filepath.Join(home, ".skaffen")` from `os.UserHomeDir()`; there is **no environment override for the store or evidence directory** (the only `os.Getenv` calls in `cmd/skaffen/main.go` are `ANTHROPIC_API_KEY` at `:659`, `:677`, `:704`). The read side fires every Orient turn: `internal/session/session.go:78` — `func (s *JSONLSession) SystemPrompt(phase tool.Phase, _ int) string` — appends `formatQualityHistory(s.signalReader)` and `s.inspiration.Inspire(s.taskDesc)` whenever `phase == tool.PhaseOrient`. The prior run filed the contamination as f-028 and noted it is "directional and adverse to S." **Failure scenario:** the operator runs the no-S arm first, then the Fallow arm on the same machine; Fallow's Orient prompt is seeded with the null arm's `QualitySignal` rows and its `Inspire` draw, so the treatment arm inherits the comparator's priors and the measured difference shrinks toward zero — a null result that is indistinguishable from "S adds nothing," which is the charter's single most consequential possible finding. Running the arms in the other order produces the opposite bias. Isolation is not achievable by configuration today; it needs either a per-arm `HOME` or a one-line store-path flag.
- **Suggestion:** Change `:40` from "identical ... stores" to "**isolated per-arm stores with identical schema and identical seed state**," and add: "isolation requires either a per-arm `HOME` or a store-path override in `cmd/skaffen/main.go:290`; name which was used. Arms sharing `~/.skaffen/mutations` are not comparable (f-028)."

### runtime-phase-verdict-has-no-operational-test

- **Severity:** P1
- **Where:** `:47` ("**Does any candidate earn a distinct runtime phase now?**") and `:95` (required output 6).
- **What:** The verdict is demanded with no stated test, so it will be answered by argument. In this runtime there are only three or four places a phasehood claim could bite, and the charter names none of them — while the runtime does not even agree with itself about what the phase list is.
- **Evidence:** Four checkable seats, all verified here. (1) **Membership:** `internal/agent/phase.go:10-16` — `phaseOrder` is a fixed six-element slice `{Observe, Orient, Decide, Act, Reflect, Compound}`, and `Advance()` at `:39-46` only increments and errors past the end, so a "side-loop" outcome has no expression. (2) **A second, disagreeing list:** `internal/tui/phase.go:11` — `var phaseOrder = []string{"orient", "decide", "act", "reflect", "compound"}` — **five elements, Observe omitted**, asserted by `internal/tui/phase_test.go:68-69` ("phaseOrder has %d entries, want 5"). The source synthesis states only that "`phaseOrder` is a fixed six-element slice"; the divergence appears to be unfiled, and it means "is S a runtime phase" has two different answers depending on which list is amended, with direct consequences for the human-operability criterion at `:39` (the breadcrumb at `internal/tui/app.go:905-912` renders the five-element list). (3) **Capability:** `internal/tool/registry.go:49-72` gives Observe/Orient/Decide a byte-identical `{read, glob, grep, ls}`, and `internal/tool/builtin.go:20-22` adds `web_search`/`web_fetch` to Orient/Decide/Act — so the distinguishable gate space is read-only / read+web / write-capable, three values for a field of twelve-plus candidates (f-061). (4) **Routing:** `internal/router/router.go:20-27` routes all six phases to `ModelOpus`. **Failure scenario (the P1 in this lens's calibration):** the run writes "S is not a distinct runtime phase now," the implementer reads it as a scheduling opinion rather than a statement about a forward-only six-element FSM plus a three-valued gate vocabulary, and ships S as a seventh `phaseOrder` entry in `internal/agent/phase.go` without touching `internal/tui/phase.go` — producing an FSM state the TUI cannot render or advance past.
- **Suggestion:** Add one sentence after `:47`: "A candidate earns a distinct runtime phase only if it names a concrete diff in at least one of: membership in `internal/agent/phase.go:10-16` (and correspondingly `internal/tui/phase.go:11`), a gate entry in `defaultGates` (`internal/tool/registry.go:49-72`), a `phaseDefaults` route (`internal/router/router.go:20-27`), or a transition trigger other than the human `/advance` (`internal/tui/commands.go:196`). State which. Absent such a diff, the answer is no and the candidate is scored as capability, policy, or artifact."

### treatment-arm-has-no-trigger

- **Severity:** P2
- **Where:** `:40` ("minimal pilots for the top two actionable designs and the no-S null") and `:36` ("Survey may be paired with Fallow if the 2×2 identification claim survives verification").
- **What:** The charter does not require any pilot arm to name what fires its treatment. For the specific pair it privileges, nothing in the runtime can fire one of them.
- **Evidence:** Every phase entry is manual — the sole caller of `Advance()` is the `/advance` command at `internal/tui/commands.go:196` — and there is no scheduler, timer, or cross-session cadence anywhere in the tree. Survey (f-064) is *defined* as "untriggered fixed-effort sampling ... on a fixed cadence against a frame chosen independently of any trigger"; the synthesis states plainly "Skaffen has no untriggered cross-session scheduler at all." Fallow (f-063) is the mirror case and is fine — its treatment is *withholding*, which needs no trigger. **Failure scenario:** the Survey arm degrades to "the operator remembers to run a sampling session," which makes the sampling cadence a function of operator attention — the exact variable Fallow exists to measure — and collapses the 2×2 the pairing was chosen for: a "Survey zero" cell becomes unreadable, because it cannot be distinguished from "the human did not run Survey this week." The identification claim the charter conditions the pairing on (`:36`) fails on the trigger, not on the statistics.
- **Suggestion:** Add to `:40`: "each pilot arm must name what fires its treatment and, where nothing in the runtime does, name the smallest mechanism added (for Survey, a fixed-cadence entry point independent of `/advance`) and count that mechanism's cost against the arm."

### topology-criterion-has-no-observable

- **Severity:** P2
- **Where:** `:39` ("Exercise the neglected dimensions explicitly: ... multi-agent/topology interaction") and `:64` ("multi-agent/topology coherence" as a scored criterion).
- **What:** The criterion is required in the matrix but no mechanism makes multi-agent interaction observable in this harness, so the cell will be filled with prose that then carries the same weight as code-verified criteria.
- **Evidence:** The v2 charter declares agent orchestration "an orthogonal topology" (`docs/research/2026-08-24-oodarcs-s-phase-tournament-v2.md:27`) and the synthesis Caveat 7 records it as a region never reached: "multi-agent topology, which the charter explicitly declares orthogonal at :27 and which no lens tested for interaction with any candidate." Skaffen is a single-process loop; there is no inter-agent channel. But there *is* exactly one concrete multi-instance interaction surface in the repo, and it is the same one that carries the run's highest-consequence finding: the shared user-global store at `~/.skaffen/mutations` (`cmd/skaffen/main.go:290`, `internal/config/config.go:34`) plus the context-file channel f-050 identified — Compound's manifest-globbed write (`*.md` in `manifestGlobs`, `internal/tool/registry.go:44-46`) lands in CLAUDE.md/AGENTS.md, which is prepended to every future session's system prompt at top precedence. Two Skaffen instances on one machine therefore interact through both, with no arbitration. **Failure scenario over weeks:** the matrix's topology row is filled with plausible prose for all shortlisted candidates, the row differentiates nobody, and it silently contributes weight to whichever candidate's advocate wrote more confidently — while the one real topology risk (a second instance reading the first's ungraded speculative material at top precedence) is never tested.
- **Suggestion:** Narrow `:64` to a named test: "multi-agent/topology coherence — assessed against the one concrete interaction surface that exists: two concurrent Skaffen instances sharing `~/.skaffen/mutations` and the Compound context-file write path. State whether the candidate's output crosses either. If a candidate cannot be assessed against that surface, mark the cell `not-assessable` and exclude it from the ordering rather than rating it."

## Verdict

The charter's pilot clause is a single sentence (`:40`) that re-issues, almost verbatim, the instruction the prior run spent six findings showing is uninterpretable — and its two most consequential words, "budgets" and "stores," are the two the runtime resolves in the worst possible way: `Tracking` defaults to `billing`, which ignores the cached context the arms differ by, and the signal store is a hardcoded user-global path with no override, so "identical" means shared. It is genuinely disciplined in requiring a pre-declared "losing pilot outcome" per shortlisted option (`:76`), which is the clause most pilot charters omit. Four narrow repairs — name the currency, change "identical stores" to "isolated stores," give the runtime-phase verdict a four-seat operational test, and require each arm to name its trigger — would make every pilot outcome readable in one direction or the other.
