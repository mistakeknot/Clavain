### sideband-go-confirmed-second-writer
- Severity: P0
- Where: `cmd/clavain-cli/sideband.go:11-26` (`writeBeadSideband`), called from `cmd/clavain-cli/phase.go:225-227`; plan lines 25 (A2), 112 (Question 5), 59 (W4 DONE WHEN proof).
- What: **Confirmed.** `writeBeadSideband` is not a hypothetical sideband — it is a shipped, actively-called, session-keyed writer of interphase-namespaced state, and its own commit history says in plain language that it is the thing A2 concluded doesn't exist. The call site's comment at `phase.go:225-226` reads verbatim: `// Sideband parity (KD 11): keep the statusline current without interphase.` The original pre-9696538 docstring (before it was generalized) read: `// writeBeadSideband mirrors interphase's _gate_update_statusline envelope`. A2 states "The `_gate_update_statusline` function that `session-start.sh` names no longer exists" and stops there — true of the shell function, false of its lineage: this Go function was written specifically to be its successor and says so twice in its own history. It writes `~/.interband/interphase/bead/<sessionID>.json`, and round-0 research (`fd-chronometry-precedence.md`) already traced `statusline.sh`'s live "Active beads" rendering code (line 308) to read exactly this path — meaning this is not dead scaffolding, it is what actually reaches the screen. Question 5 literally asks "is there a sideband writer this plan did not find?" — the answer, verifiable in the same repo the plan is patching, is yes.
- Evidence: `git log --follow --oneline -- cmd/clavain-cli/sideband.go` → `9696538`, `6216044` ("feat(goal): interband sideband parity from sprint-advance (KD 11, task-12)"); `git show 9696538^:cmd/clavain-cli/sideband.go` shows the original `_gate_update_statusline`-mirroring docstring; `cmd/clavain-cli/phase.go:225-227`.
- Suggestion: N/A — see remediation.

### sideband-go-permanently-invisible-to-w3
- Severity: P1
- Where: `cmd/clavain-cli/sideband.go:18-23` vs plan §W3 (`tests/structural/test_session_registers.py`, SCANNED_DIRS = hooks/, scripts/, commands/, skills/, agents/).
- What: Even after A2 is corrected and sideband.go is pulled into scope, W3's structural test as specified cannot verify it, for two independent reasons this lens exists to catch. First, `cmd/` is not a scanned root (already noted as a settled fact for the other 7 bare sites). Second — the sideband-specific wrinkle — sideband.go's chain is a **two-statement sequential reassignment** (`sessionID = os.Getenv("CLAUDE_SESSION_ID")` then `if sessionID == "" { sessionID = os.Getenv("CLAUDE_CODE_SESSION_ID") }`), not the ternary/coalesce shape (`${A:-${B:-C}}`, `A // B // C`) W3's accepted-forms list is written against. A Go-aware extension to W3 that simply reuses the existing regex family would false-flag this file as an unconverted bare read even though its precedence is already correct end-to-end for the two registers it has — the walker needs a distinct accepted form for the Go if/reassignment idiom, not a copy-paste of the shell/jq patterns. This is the exact "language the walker's patterns don't match" failure mode this lens's own Severity Calibration names for Python (P1 in the agent brief), now demonstrated concretely in Go on a file the plan's own review process (Question 5) flagged as unresolved.
- Evidence: `cmd/clavain-cli/sideband.go:18-23`; plan line 53 (accepted forms: canonical chain, jq chain, assignment/export, helper definition — none matches the Go if-reassignment shape).
- Suggestion: Don't extend W3's existing regex set to `cmd/`. Either (a) factor the chain into one shared Go helper (mirroring `hooks/lib.sh`'s `clavain_session_id`) and have the structural test's Go-mode accept only "calls the helper" or "is the helper's own definition" — the same one-accepted-form strategy W3 already uses for shell — or (b) skip regex entirely for Go and add a `go vet`-style AST check, since Go's own tooling can distinguish an expression's identifiers precisely where line-grep cannot.

### sideband-fix-cheaper-than-w4-test
- Severity: P2
- Where: plan §W4 (new `tests/shell/session.bats`, new `_interphase_session_id` helper) vs `cmd/clavain-cli/phase.go:225-226` comment ("keep the statusline current **without interphase**").
- What: The plan's own codebase says, in the exact call site A2 missed, that interphase's claim/marker mechanism is being architecturally superseded by the sideband/interband path for statusline purposes ("brainstorm KD 11"). W4 nonetheless builds new test infrastructure (`session.bats`, a new interphase-side helper) to prove session-correctness of the mechanism the code comments say is being phased out, while the mechanism the comments say is its replacement (`writeBeadSideband`) gets neither the fix nor a test in this plan. That is a fix landing one layer below where the architecture is already moving — cheaper and more durable to spend the equivalent effort making `writeBeadSideband` accept a real caller-supplied session id (today `phase.go:227` passes `""` unconditionally, discarding whatever identity the calling command actually has, exactly the "pass empty to opt out of the highest-priority register" pattern flagged elsewhere in this plan for `hooks/lib.sh`) than to harden the retiring path.
- Evidence: `cmd/clavain-cli/phase.go:226-227` (`_ = writeBeadSideband("", beadID, toPhase, "sprint-advance")`); sideband.go doc comment "so callers stop threading ids."
- Suggestion: Add `sideband.go`'s two-register chain (or a shared Go helper covering it) to this plan's Go-scope extension, and pass a real session id from `phase.go`'s call site instead of `""`, rather than only adding new interphase-side test scaffolding in W4.
