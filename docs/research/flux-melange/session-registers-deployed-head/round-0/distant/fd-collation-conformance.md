## Findings

### cmd-clavain-cli-unconverted-getenv

- **Severity:** P0
- **Where:** `cmd/clavain-cli/phase.go:267` (`phaseAttributionSessionID`), `cmd/clavain-cli/claim.go:206` (`cmdBeadClaim`), `:319` (release ownership check), `:366` (heartbeat refresh), `cmd/clavain-cli/budget.go:585`, `cmd/clavain-cli/evidence.go:150`, `cmd/clavain-cli/init.go:128` — 7 sites, all `sessionID := os.Getenv("CLAUDE_SESSION_ID")` with no `CLAUDE_CODE_SESSION_ID` fallback (some then substitute the literal string `"unknown"`, e.g. `claim.go:207,320,367`).
- **What:** W2's conversion list is exhaustive over hooks, scripts (`lib-routing.sh`, `dispatch.sh`), commands, skills, and agents, but never mentions `cmd/`. W3's structural test walks only `("hooks", "scripts", "commands", "skills", "agents")` (`tests/structural/test_session_registers.py:29`) and its `READ` regex (`\$\{?CLAUDE_SESSION_ID\b|env\.CLAUDE_SESSION_ID\b`) matches shell and jq syntax only — it would not match Go's `os.Getenv("CLAUDE_SESSION_ID")` even if `cmd/` were added to `SCANNED_DIRS` tomorrow. These are not idle call sites: `hooks/lib-recovery.sh:183` shells out to `clavain-cli bead-release`, and `commands/work.md:86` calls `clavain-cli bead-heartbeat "$CLAVAIN_BEAD_ID"` on every task-execution iteration. In a session whose start hook did not fire, `bead-claim`/`bead-release`/`bead-heartbeat`/evidence-manifest/billing-attribution all resolve `sessionID=""` (or `"unknown"`) inside the binary that W5 is busy fingerprinting byte-for-byte against `origin/main` — the exact mk-hxgi failure shape, now in Go, verified green by the plan's own matrix.
- **Evidence:** `cmd/clavain-cli/sideband.go:17-23` shows the fix pattern was already known inside this same package (`sessionID = os.Getenv("CLAUDE_SESSION_ID"); if sessionID == "" { sessionID = os.Getenv("CLAUDE_CODE_SESSION_ID") }`, comment cites "Sylveste-23k") — 1 of 8 `os.Getenv("CLAUDE_SESSION_ID")` occurrences in the package converts correctly; the other 7 are bare. This is inconsistency, not an unknown pattern.
- **Suggestion:** Add a `sessionRegisterID()` Go helper mirroring `sideband.go`'s chain, replace the 7 bare call sites, and extend W3 with a second regex pass (or a small `go vet`-style grep) over `cmd/**/*.go` for `os\.Getenv\("CLAUDE_SESSION_ID"\)` not immediately followed by a `CLAUDE_CODE_SESSION_ID` fallback. One diff hunk in Go, one added directory + pattern in the Python test — not a rewrite of either.

### w5-compared-roots-incomplete-and-inconsistent

- **Severity:** P1
- **Where:** plan §W5 step 4 (`git ls-tree -r origin/main -- hooks scripts bin commands agents skills config .claude-plugin`) vs. plan §Questions, item 3 ("Is comparing seven roots the right surface...").
- **What:** Two independent problems. First, the plan cannot consistently count its own comparison surface: step 4 lists 8 tokens, Question 3 calls it "seven roots" — a bibliographic formula that misstates its own leaf-count invites exactly the kind of silent omission collation is built to catch. Second, and more substantively: the repository root actually contains `agents/ bin/ cmd/ commands/ config/ docs/ galiana/ hooks/ schemas/ scripts/ skills/ tests/` (verified via `ls -d */`) plus top-level files `agent-rig.json`, `AGENTS.md`, `HANDOFF.md`, `CHANGELOG.md`, `kimi.plugin.json`, and 8 `interlab-*.{sh,md}` scripts. None of `cmd/`, `docs/`, `galiana/`, `schemas/`, `tests/`, or any top-level file is in the compared-roots list, so a stale or hand-edited copy of any of them in the installed plugin cache produces zero findings — not a `MISSING`/`STALE`/`EXTRA` line, just silence, and the check's own summary line has no field that would let a reader distinguish "compared and equal" from "never looked."
- **Evidence:** `interlab-route-prompt.sh:89` (top-level, uncompared) contains `check "code-set-state-claimed" "set-state.*claimed_by|claimed_by.*CLAUDE_SESSION_ID"` — a live, session-register-sensitive regex check sitting entirely outside every root W5 examines and every directory W3 walks. `cmd/` alone (the Go source the CLI binary is built from, and the subject of finding `cmd-clavain-cli-unconverted-getenv` above) is the largest unexamined gathering: a stale cache copy of `cmd/clavain-cli/claim.go` would be invisible to `clavain-deployed` even though the CLI-probe step (W5 step 5) only checks the *built binary's* runtime behavior on one specific flag (`policy audit --zzz`), not whether the source behind it matches HEAD content-wise the way hooks/scripts/etc. do.
- **Suggestion:** Fix the 7-vs-8 count first (cheap, and a reviewer's trust in the rest of the enumeration rides on it). Then either (a) extend step 4's root list to the whole tracked tree minus a documented exclude-list (docs/, tests/, *.md prose) and accept the longer finding list Question 3 already raises as an option, or (b) explicitly scope the check's summary line to say "N of M top-level entries compared" so a green run is legible as bounded rather than complete. Given finding `cmd-clavain-cli-unconverted-getenv`, `cmd/` specifically should not stay excluded — it is exactly the kind of source-vs-cache drift mk-f0mz was named for.

### structural-test-python-idiom-blind-spot

- **Severity:** P2
- **Where:** `tests/structural/test_session_registers.py:33-34` (`READ` and `ACCEPTED` regexes); `SCANNED_SUFFIXES = {".sh", ".md", ".py", ".json", ".bash"}` at line 30.
- **What:** I checked the two evasions this lens's own generated brief proposed against the actual test file and its pinned `test_classifier_examples` table — both are wrong and I am dropping them: `SID="$CLAUDE_SESSION_ID"` is explicitly pinned as `accepted=False` (caught), and `CLAUDE_SESSION_ID=${CLAUDE_SESSION_ID:-}` is also caught because stripping the `ASSIGNMENT` match still leaves a `READ`-matching remainder (`${CLAUDE_SESSION_ID:-}`), so the assignment exemption's `not READ.search(...)` guard correctly refuses to exempt it. The real, verified gap is narrower: `READ = re.compile(r"\$\{?CLAUDE_SESSION_ID\b|env\.CLAUDE_SESSION_ID\b")` recognizes only the shell `$`-sigil and the jq `env.`-prefix idiom. `.py` is a scanned suffix and `scripts/` (a scanned dir) already holds ~20 Python files (`scripts/orchestrate.py`, `scripts/context-gateway.py`, etc.). A Python reader written as `os.environ.get("CLAUDE_SESSION_ID")` or `os.environ["CLAUDE_SESSION_ID"]` contains neither a `$` sigil nor the literal substring `env.CLAUDE_SESSION_ID` (the char before `CLAUDE_SESSION_ID` is `[` or `"`, not a bare `.`), so it would never trip `READ` at all — not "accepted," simply invisible, in a file type and directory the test already claims to police.
- **Evidence:** `grep -rln 'CLAUDE_SESSION_ID' --include="*.py" hooks/ scripts/ commands/ skills/ agents/` returns nothing today — no live instance of this gap exists yet, so this is prospective, not a current miss. Confirmed via direct execution of the regexes against both proposed lens evasions and against the two Python idioms above.
- **Suggestion:** Add a third `ACCEPTED`/`READ` pair for the Python idiom (`os\.environ(\.get)?\(?\[?["']CLAUDE_SESSION_ID`) mirroring the shell/jq treatment, even with zero current offenders — the cost is two regex lines, and it closes the one suffix/directory combination the test already scans but cannot actually read.

## Verdict

The plan's register fix is real and, per `hooks/lib-sprint.sh` and `tests/structural/test_session_registers.py` (already present, uncommitted, in this worktree), substantially implemented — but its enumeration stops at the plugin's shell/prose surface while `cmd/clavain-cli` runs the same claim/release/heartbeat/evidence/billing logic in Go, unconverted and unguardable by the chosen regex family; that is a P0 recurrence of the exact defect this plan exists to close. The rig check's comparison surface is bounded in a way its own text can't consistently describe, and at least one real artifact (`interlab-route-prompt.sh`) sits outside it today.
