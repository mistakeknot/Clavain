## Findings

### scout-collection-half-is-decide-verbatim
- **Severity:** P1
- **Where:** target §Candidate-generation requirement (60,73), disposition of Scout under contract-equivalence clustering
- **What:** Finding (1) rests on one factual claim — that a collection half gated to `read+web, no write/bash` is "the only candidate delta not present in any current phase." That claim is false on the trace. `internal/tool/builtin.go:19-22` registers `web_search` and `web_fetch` for `PhaseOrient, PhaseDecide, PhaseAct`; `internal/tool/registry.go:53-55` gives Decide `read, glob, grep, ls` and nothing else. Decide's live, shipped gate signature is therefore exactly `{read, glob, grep, ls, web_search, web_fetch}` — read + web, no write, no bash. The proposed collection half has a delta of zero against a phase that already exists, and Orient differs from it by exactly one read-only tool (`quality_history`, builtin.go:27-28). Finding (1) also concedes its second half is "Orient's tool set with new vocabulary." So both halves of the two-operation Scout fail hard gate 1 (semantic distinction) and lesson 2 (enforceable delta) by the charter's own criteria. Finding (2) holds: Scout's search-behavior reading has no contract residue once the gate claim dies, and Trace — pre-registered, budgeted, detector and detection window fixed *before* injection — is the only version of that cluster with a delta that survives inspection. This is not a taste call between elegant and reckless; it is decidable, and finding (1) loses on a checkable fact.
- **Evidence:** `internal/tool/builtin.go:19-22` (`webPhases := []Phase{PhaseOrient, PhaseDecide, PhaseAct}`); `internal/tool/registry.go:49-58` (Observe/Orient/Decide all `read, glob, grep, ls`); `internal/tool/web_search.go:51`, `internal/tool/web_fetch.go:52` (tool names); `internal/tool/registry.go:140-153` (`RegisterForPhasesWithConstraint` is the only mechanism that can create a gate delta, and it was not used for web).
- **Suggestion:** Record Scout's disposition as: absorbed into Trace by contract-equivalence; the collection/interpretation split is rejected with the explicit reason that the collection half is byte-identical to shipped Decide. Do not carry a "Scout-collection" entry onto the shortlist.

### enforcement-axis-is-three-valued
- **Severity:** P1
- **Where:** target §Per-candidate contract item 7 (75-89), §Lessons item 2 (37)
- **What:** The reason finding (1) reached for a gate delta and found a phantom is structural: Skaffen's entire gate space contains only three distinguishable signatures — read-only (`Observe`), read+web (`Orient`/`Decide`, differing by one read tool), and write-capable (`Act` unconstrained; `Reflect`/`Compound` the same set under `RateLimit`/`AllowedGlobs`). Twelve candidates cannot be separated in a 3-valued space. If item 7 keeps reading as "name the capability delta," every candidate whose novelty is *temporal or authority-shaped* rather than capability-shaped — Trace (detector fixed before injection), Assay (re-marking material it did not produce), Reprove (staleness-triggered removal of authority) — will be graded "not runtime-enforceable" for lacking a delta the codebase's gate vocabulary cannot express, while any candidate that merely re-labels Decide's tool set will look enforceable to a careless reading. The gate matrix is not the only enforcement surface in the repo: `GateConstraint` already carries `RateLimit` and `RequirePrompt` (registry.go:16-27), constraints are enforced at `Execute` (registry.go:225-260), and authority/state enforcement lives outside `tool/` entirely.
- **Evidence:** `internal/tool/registry.go:49-71` (six phases, three signatures); `internal/tool/builtin.go:19-22` (web collapses Orient/Decide/Act toward each other); `internal/tool/registry.go:16-27, 225-260` (rate-limit and prompt constraints are the only per-phase enforcement primitives beyond membership); `internal/tool/tool.go:44-53` (`Phase` is a string — adding a letter is free, which is exactly why the letter must be earned elsewhere).
- **Suggestion:** Score each contract's item 7 on four named dimensions and require the mechanism, not the adjective, in each: capability (gate membership/constraint), state (a pre-registered commitment checked at write time), routing (model/budget selection), authority (grade + read filter + expiry). A candidate is runtime-enforceable if it has a checkable delta in any one dimension.
- **Remediation:** Amend §Per-candidate contract item 7 to read "Capability, state, routing, or authority delta needed for runtime enforcement — name which of the four and the exact enforcement point," and add to §Lessons item 2 the settled fact that Skaffen's gate matrix distinguishes only three signatures (read-only / read+web / write-capable), so a bare tool-gate delta is neither necessary nor sufficient for phasehood.

## Verdict
The contradiction is decidable and finding (1) loses: the gate signature it calls unique — read+web, no write/bash — is Decide's shipped signature verbatim (`builtin.go:19-22` + `registry.go:53-55`), so the two-operation Scout has a delta of zero on both halves and Trace's contract-equivalence absorption stands. The contradiction's real payload is that Skaffen's gate space is only 3-valued, which makes "capability delta" a trap the tournament will keep falling into unless item 7 is widened to capability/state/routing/authority with the enforcement point named.
