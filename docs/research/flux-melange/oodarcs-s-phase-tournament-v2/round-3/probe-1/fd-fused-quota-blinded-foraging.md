## Findings

### misaddressed-compound-bucket

- **Severity**: P0
- **Where**: `internal/mutations/aggregate.go:93,101-136` (write side) vs `internal/mutations/inspire.go:21,43-59` (read side); `internal/mutations/best.go:9`; `internal/mutations/store.go:99-140`; target `:128`, `:157`
- **What**: Skaffen assigns the per-task-type bucket with two different, unreconciled classifiers. Compound writes via `mutations.Aggregate` → `inferTaskType(records)`, a tool-call-pattern heuristic. Orient reads via `Inspire(taskDesc)` → `ClassifyTask(description)`, a keyword matcher. Nothing reconciles them, and `inferTaskType`'s switch (aggregate.go:125-136) can return only `TaskDocs`, `TaskFeature`, `TaskRefactor`, `TaskBugFix`, `TaskGeneral` — **`TaskOptimization` is never returned by any write path**, while `ClassifyTask` returns it on any description containing "optimize", "perf", or "faster" (inspire.go:50-51). `optimization.jsonl` is therefore a permanently empty logbook that Orient consults on every optimization task, returning `"No history for optimization tasks yet."` (best.go:26) forever, regardless of how many optimization sessions have actually run.
- **Evidence**: `Aggregate` is the only producer of `sig.TaskType` (aggregate.go:93) and `WriteForType` routes on it (store.go:113); `BestApproach` reads `ReadRecentForType(tt, 50)` with `tt` from `ClassifyTask` (best.go:9, inspire.go:21-25). The 50-row window at best.go:9 is a sliding window, so misrouted rows are not merely delayed — once the wrong file grows past 50 they are unreachable.
- **Tournament consequence**: the charter's duplication test (`:128`) and the "no S / capability in Compound" option (`:67`) are both scored on the assumption that Compound's per-type compounding channel works. It does not: it is not thin, it is *misaddressed*, with at least one whole bucket that can never receive an entry. The no-S null is being credited with a capability whose evidence channel has never carried a signal, so every transfer/synthesis candidate is over-penalised on duplication. Separately, the pilot clause "identical task buckets and recording paths" (`:157`) is satisfiable only vacuously, since bucket assignment on the write side is computed from arm behaviour rather than pre-registered.
- **Suggestion**: thread the `TaskType` already computed by `ClassifyTask` at session start (session.go:87) through `agent.go:248` into `Aggregate`, so write bucket == read bucket by construction; delete `inferTaskType` or demote it to a fallback used only when no description exists.

### fallow-contract

- **Severity**: P1
- **Where**: target `:43` (affirmative null), `:71` (policy-class slot), `:142-147` (pilot arms); `internal/tool/registry.go:15-26,64-65,243-256`
- **What**: FALLOW is a policy-class candidate whose entire output is an allocation change and a number. Contract, eleven fields:
  1. **Input/preconditions** — a pre-registered window of k consecutive sessions in one bucket; requires the allocation register named in the Warrant contract (settled fact 3), since FALLOW emits no artifact for the epistemic-separation gate to grade.
  2. **Transformation** — sets S-tasking to zero for the window. Nothing else changes.
  3. **Output/consumer** — one number per window: spontaneous exploration turns per session inside Observe/Orient/Act, countable today from the existing evidence record's `tool_calls` (aggregate.go:14-24) with no new instrumentation. Consumer is the tournament's no-S specification and the pilot's budget equalisation, not Orient.
  4. **Authority/storage/read filter/expiry/negatives** — grade is *measurement*, not claim; stored in the allocation register, never in `quality-signals.jsonl`; read filter is total — Orient must not read it, because it is about the loop, not the task; expires when the next FALLOW window supersedes it; a zero reading is the affirmative finding and is retained, not discarded.
  5. **Trigger/pace** — signal-driven, not calendar: fires when the marginal grade of the last item minted under the current S warrant falls below the previous window's FALLOW reading. Pace layer sits below session and above roadmap.
  6. **Re-entry** — none into the task loop; re-enters at the warrant-renewal decision only.
  7. **Runtime delta** — `GateConstraint` (registry.go:15-26) can express only a *ceiling*: `RateLimit`, enforced at registry.go:243-256 and reset on every phase transition (registry.go:119-121). Skaffen has no floor, no zero-for-window, and no cross-session counter. FALLOW therefore demands a strictly larger enforcement delta than Scout (a report-emitting candidate needs no gate change at all) and than Decide, which per settled fact has no enforceable delta of any kind.
  8. **Overlap** — none. It is the only candidate whose product concerns the loop rather than the task.
  9. **Failure/Goodhart** — the loop learns the window and phase-shifts exploration to just after it. Detectable, because the post-window spike is measured by the same instrument.
  10. **Cheapest pilot / losing condition** — 10 sessions at quota zero, count exploration turns. FALLOW loses, and every S candidate loses with it, if spontaneous exploration already meets or exceeds the proposed S quota: in that case S is renaming existing behaviour and charter `:43` resolves for the null.
  11. **Classification** — policy/side-loop. Explicitly not a semantic phase and not an artifact.
- **Evidence**: charter `:142` requires "equal-budget traces" across arms, but no clause anywhere fixes the incumbent's current exploration budget, and no code measures it. The pilot as written compares an arm with a known S budget against an arm with an unknown one and calls the difference the effect of S.
- **Suggestion**: run FALLOW as a zeroth arm before the two-arm pilot; treat its reading as the denominator for every "added exploration" claim in `:157`.

### survey-contract

- **Severity**: P1
- **Where**: target `:70-71`, `:142` (corpus incl. no-benefit cases), `:108` (comparative criteria); `internal/mutations/inspire.go:20-40`
- **What**: SURVEY is untriggered fixed-effort sampling on a pre-registered frame; its product is base rates about the environment, not leads about the current task. Abbreviated contract: input = a fixed per-window effort budget and a sampling frame chosen independently of any trigger; transformation = sample the frame and record whether an exploitable cross-domain mechanism exists, whether or not anyone asked; output = a prevalence figure consumed by the pilot's false-transfer scoring (`:153`); authority = base-rate measurement, stored outside the validated store, read only by the warrant-renewal decision, expiring on the next survey; trigger = fixed cadence *by construction*, which is the point; runtime delta = an untriggered cross-session scheduler, which Skaffen entirely lacks (all phase entry is manual, `internal/tui/commands.go:196-201`); overlap = none, because every incumbent read path is task-conditioned; failure mode = the frame drifts to where the surveyor already expects yield; losing condition = the surveyed prevalence is indistinguishable from the triggered candidates' hit rate, in which case the trigger is costless and SURVEY is redundant; classification = capability, not a phase.
- **Evidence / why it does not merge with FALLOW under the sensor-signature clustering rule** (`:42`): the two instruments read orthogonal axes. FALLOW varies effort at fixed environment; SURVEY varies the environment reading at fixed effort. Under a rich patch with a broken trigger, FALLOW reads high and SURVEY reads high. Under an exhausted loop in a rich patch, FALLOW reads zero and SURVEY reads high. Under a genuinely empty field, both read zero. FALLOW alone cannot separate "loop stopped exploring" from "patch is empty"; SURVEY alone cannot separate "patch is rich" from "trigger is broken". Only the pair identifies the confound — and every trigger-conditioned candidate in the field (Scout, Trace, Stress-test) is fishery-dependent by construction and can never observe that a patch has become rich again.
- **Suggestion**: add the FALLOW×SURVEY pair to the charter's fusion tally as a single fusion-emergent discriminator, and require every trigger-conditioned candidate to state which of the four cells its sensor cannot distinguish.

### operator-elected-landings

- **Severity**: P1
- **Where**: `internal/agent/agent.go:246-253`; `internal/agent/phase.go:39-47`; `internal/tui/commands.go:196-201`; `cmd/skaffen/main.go:216-222`; target `:157`
- **What**: The quality store's entry condition is survival to Compound — `if phase == tool.PhaseCompound && a.evidenceDir != ""` (agent.go:247). Phase advance is **manual only**: `AdvancePhase` has exactly one caller, the TUI `/advance` command (commands.go:196-201), and there is no automatic transition anywhere. In print mode a signal is written only when the operator explicitly passes `--phase compound` (main.go:218). So the store is populated by discretionary operator election: a session lands only if a human chose to walk it all the way to Compound. Sessions abandoned in a rabbit hole — the characteristic failure mode of exactly the exploration candidates under test — never enter the record.
- **Evidence**: `phaseOrder` (phase.go:10-17) is linear and `Advance` errors past Compound (phase.go:41-43); nothing calls it but the slash command. Landings are recorded; catch is not counted anywhere.
- **Tournament consequence**: censoring at Compound favours the S arm (its worst outcomes are unrecorded), while the settled throughput self-certification favours the null. Two biases of opposite sign and unmeasured magnitude means the pilot's net direction is not merely noisy but uninterpretable, and no threshold predeclared under `:157` can be honest. Warrant renewal is then decided on a cohort whose membership rule is set by the behaviour under review.
- **Suggestion**: emit a terminal `QualitySignal` on session end regardless of the phase reached, carrying an `entry_reason` field (`compound` | `abandoned` | `error`), so `ParetoFront` (signal.go:90) can still be computed over landings while the catch total stays visible; report the marginal grade of the last row minted under each arm's warrant, never the mean.

## Verdict

The tournament is being run over a compounding channel that is misaddressed rather than thin — Compound writes to a tool-inferred bucket, Orient reads a description-inferred one, and `optimization.jsonl` can never receive an entry — so the no-S null is credited with a capability that has never functioned and every transfer candidate is over-penalised on the duplication test. The field's under-filled policy slot is fillable: FALLOW and SURVEY are a two-instrument identification pair, not two candidates, and jointly they are the only thing in the field that can separate a depleted patch from a stopped forager. Both pilot arms land into a store whose entry condition is a human choosing to type `/advance`, which is the purest discretionary high-grading channel available and leaves the pilot's net bias sign unknown.
