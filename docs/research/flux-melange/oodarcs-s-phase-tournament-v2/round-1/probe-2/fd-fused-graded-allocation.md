## Findings

### warrant-contract-and-the-inverted-separation-gate
- **Severity**: P0
- **Where**: §Hard gates (99) "epistemic separation of speculative and validated material"; §Candidate-generation requirement (71) mandates a policy-changing candidate; §Per-candidate contract field 7 (85). Runtime evidence: `internal/costrouter/complexity.go:98-127`, `internal/costrouter/costrouter.go:73-80`, `internal/agentloop/types.go:124-125`, `internal/mutations/aggregate.go:56-93`.
- **What**: The separation gate grades *products*. A candidate whose output is an allocation change (Divert, and any policy-layer S) has no product, so it clears the hardest gate at zero cost, while every candidate that honestly emits a graded, expiring report must survive the full four-part test. The gate therefore ranks candidates in inverse order of governability. The missing object is the **warrant**: the tasked, graded, expiring licence to spend, which is markable even when the candidate emits no report. Filed as a fused candidate contract (fusion 1: optimal-foraging × epistemic provenance).
  - *Warrant contract*: (1) input = a depletion/yield estimate plus a named issuer; (2) transformation = converts an internal state estimate into a bounded, expiring spend licence; (3) output = a warrant row (issuer, estimate, grade, cap, expiry, consumed-by), consumer = the next turn's router and the post-hoc reader; (4) grade = the grade of the *estimate*, not of any claim; namespace = the allocation ledger, never the Orient injection path; expiry = the licence lapses on cap or clock, whichever first; failed probes debit the cap and are retained; (5) trigger = measured depletion, pace layer = per-turn/per-session; (6) re-entry = the ordinary loop, with the warrant id attached to every turn it paid for; (7) runtime delta = the smallest one in the field — `Evidence.ModelReason` already exists at `types.go:125` and already records `"cheap-turn-limit"`; carry a warrant id alongside it and stop dropping both at `aggregate.go:56-93`; (11) classification = capability/policy object, not a phase.
- **Evidence**: Skaffen already runs an unwarranted allocation channel with exactly the failure shape. `complexityTracker.shouldEscalate()` (complexity.go:100-127) converts three ungraded internal counters into a model upgrade; `costrouter.go:74-75` calls `r.tracker.reset()` at the *moment of escalation* — despite the doc comment at complexity.go:129-130 claiming reset happens on successful completion — so the estimate that authorized the spend is destroyed before the spend is evaluated. The reason string survives one hop into `Evidence.ModelReason` (types.go:125) and is then dropped by `aggregate.go:56-93`, which keeps only token efficiency, turn count, complexity tier and error rate. No reader ever sees who authorized what.
- **Suggestion**: Add a fourth hard-gate clause for allocation-shaped candidates: "names the graded, expiring warrant that authorizes the spend, and the record that survives the spend." Score Divert against it. Implementation delta is one field: propagate `ModelReason` (+ warrant id) through `mutations.QualitySignal` instead of discarding it at aggregate.go.

### field4-conflates-claim-expiry-with-cost-record-retention
- **Severity**: P1
- **Where**: §Per-candidate contract field 4 (82) vs §Lessons item 5 (41) and §Hard gates (100) "a bounded trigger/stop rule". Runtime evidence: `internal/session/session.go:78-91`, `internal/mutations/inspire.go:20-40,87-108`, `internal/costrouter/costrouter.go:75`.
- **What**: Field 4 asks for one expiry policy over two different objects: the speculative *claim* (which must lapse so it cannot become evidence) and the *cost record* of the failed probe (which must persist because it is the base rate that makes the stop rule computable). As written, a contract answering "expires in N days" deletes the depletion estimate that its own field 5 trigger depends on, and a contract answering "retained indefinitely" has no read filter — so hard-gate adjudication between "epistemic separation" and "bounded stop rule" becomes a coin flip that decides which survivors reach the shortlist.
- **Evidence**: The retention side is already a live laundering path, not an abstraction. `JSONLSession.SystemPrompt` (session.go:78-91) builds Orient's prompt by string concatenation: quality history, then `mutations.FormatInspiration(...)`, which (inspire.go:87-108) joins `BestHistory`, `Suggestions`, and raw `cass search` stdout with no grade marker, no namespace, and no filter. Anything retained and reachable by `Store.Inspire` enters Orient as unmarked prose. The deletion side is equally live: `costrouter.go:75` resets the depletion counters on use, so Skaffen currently has zero patch memory across escalations.
- **Suggestion**: Split field 4 into 4a (claim grade + expiry + read filter) and 4b (cost-record retention: what is kept forever, in which store, and the explicit statement that this store is not reachable from `SystemPrompt`/`Inspire`). Require every shortlisted contract to answer both.

### equal-budget-has-no-declared-meter
- **Severity**: P1
- **Where**: §Pilot contract (142) "Compare equal-budget traces", (157) "identical task buckets and recording paths", against (140) which bans TokenEfficiency/TurnCount and (152) which then scores "time/turns to useful probe". Runtime evidence: `internal/router/budget.go:20-59`.
- **What**: The pilot equalizes a currency it never names, and the two currencies actually implemented are not interchangeable in the direction that matters. `BudgetTracker.Record` (budget.go:52-59) meters either `"billing"` (input+output) or `"context"` (plus `CacheCreationInputTokens` + `CacheReadInputTokens`). The S-arms differ from the null precisely by parking speculative material in context every turn: under billing that material is nearly free after the first cache write; under context it is charged in full. So "equal budget" hands the exploration arm either a subsidy or a tax depending on an unstated config field, and the arm's ranking flips with it.
- **Evidence**: budget.go:52-59 (`if bt.tracking == "context" { spent += CacheCreation + CacheRead }`), default `"billing"` at budget.go:36-39. The charter forbids the throughput meters at line 140 as *outcomes*, which is right, but leaves no declared *input* currency at all.
- **Suggestion**: Pre-register the budget currency as a tasking input distinct from the outcome set — e.g. cap each arm at N warranted tool-calls plus a fixed `tracking: "context"` token cap — and record the meter setting in the pre-registration so a reader can tell whether an arm was subsidised.

### cluster-key-omits-probe-cost
- **Severity**: P2
- **Where**: §Candidate-generation requirement (60) "cluster contract-equivalent names"; §Lessons item 6 (42) "unless their contracts, triggers, outputs, or authority differ".
- **What**: The clustering predicate is a disjunction over contract, trigger, output, and authority — spend is absent. Two operations that share all four but differ by an order of magnitude in probe cost (a cheap indicative screen versus a costly dispositive test) merge into one candidate, and the merged contract can only quote one field-10 pilot cost. Since the merge happens before scoring (line 73), the variable that decides whether a candidate is affordable is erased before anyone allocates against it.
- **Evidence**: The already-clustered field shows the effect: the screen/test ladder is carried inside a single candidate rather than as a cluster boundary, and Skaffen's own gate matrix distinguishes tools by constraint cost, not verb — `internal/tool/registry.go:63-71` separates Reflect's `edit` (`RateLimit: 3, RequirePrompt: true`) from Compound's `edit` (`AllowedGlobs: manifestGlobs`); same verb, same output, different spend and different authority.
- **Suggestion**: Make the cluster key an explicit triple — (tasking predicate, spend order-of-magnitude, grade) — and require any merge that spans a spend order of magnitude to be recorded as a sub-contract with its own field 10.

## Verdict
The tournament's hard gates grade products but not spends, so the one candidate class the charter explicitly mandates — a policy-changing S — passes the epistemic-separation gate by emitting nothing, and Skaffen's existing escalation channel shows what that looks like in production: an ungraded estimate that upgrades the model, erases itself on use, and never reaches a reader. The fused answer is the Warrant contract plus a fourth gate clause; the two supporting P1s (a single expiry clock over two objects, and an unnamed budget meter) are what currently makes field 4 unscoreable and the pilot's "equal budget" unfalsifiable.
